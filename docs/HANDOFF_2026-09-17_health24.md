# Handoff 2026-09-17 — онкоцентр Health24 підключено в канон

Третій заклад у `lpz` (після ЛШМД `43342788` і Хотинської `02005875`) — **ОКНП
«Буковинський клінічний онкологічний центр»**, ЄДРПОУ **43343870**. Перше
джерело даних не helsi.pro, а **Health24** (`h24.ua` / `mis.h24.ua` /
`ehr.h24.ua`) — окрема МІС, інша структура API.

## Що зроблено

1. **Сирі дані витягнуто з `mis.h24.ua`** (вкладка браузера, залогінена як
   лікар-власник) і збережено у `~/Documents/LSMD/raw/h24/`:
   - `hospitalizations_43343870.json` — 16 281 госпіталізація
   - `patients_43343870.json` — 72 871 пацієнт
   - `journal_events_43343870_*.json` (10 файлів, part1a/b + 2024Q1-4 +
     2025Q1-4) — 403 577 поліклінічних подій (398 596 унікальних після
     дедупу), період 01.01.2024 → 16.09.2026. `crossing_visits` видалено з
     усіх файлів (дублювало інші записи, роздувало розмір у 18 разів).

2. **Raw-таблиці** `lpz.lpz_raw_h24_hospitalizations` / `_patients` /
   `_journal_events` — залиті через `scripts/load_json_raw.py --table
   lpz_raw_h24_<тип> --org-edrpou 43343870`.

3. **Канон** — чотири повторювані SQL-скрипти в `scripts/sql/`:
   - `raw_to_canon_h24_hospitalizations.sql` — `id_case` = h24-івський
     `id` напряму (унікальний bigint, на відміну від helsi не треба
     розбирати номер картки); `patient_id`/`helsi_record_id` — детерміновані
     UUID через `md5('h24|<org>|<тип>|<id>')::uuid`.
   - `raw_to_canon_h24_patients_enrich.sql` — повний реєстр 72 870
     унікальних пацієнтів (дедуп по `id`, DISTINCT ON).
   - `raw_to_canon_h24_empl.sql` — відділення (3) + лікарі зі стаціонару
     (51) + донабір `department_structure_id`/`doc_resource_id` у вже
     завантажені госпіталізації.
   - `raw_to_canon_h24_journal_events.sql` → `lpz_episodes` (398 596,
     поліклінічні візити) + розширення `lpz_empl` лікарями з журналу (ще
     64, разом 115).

   Підсумок у базі: `lpz_organizations` 1, `lpz_departments` 3,
   `lpz_empl` 115, `lpz_patients` 72 870, `lpz_hospitalizations` 16 281,
   `lpz_episodes` 398 596.

4. **Ручні виправлення в Supabase** (НЕ в git, зроблені напряму через MCP
   `apply_migration`/`execute_sql` — якщо треба зробити повторюваними,
   оформити як файли в `database/migrations-lpz/`):
   - `lpz_departments.direction` — заповнено (`СП ОНКОХІРУРГІЯ` →
     хірургічний, решта → терапевтичний). Без цього блоки напрямків на
     `entry.html` були порожні (жорстко прив'язані до цих двох значень).
   - `lpz_empl.role` — заповнено `'doctor'` для всіх 115 (раніше `NULL`).
     Без цього Ординаторська й «Чергові лікарі» були порожні.
   - **Продуктивність (важливо, стосується й ЛШМД):** `lpz_kpi_by_doctor`
     (обидва overload), `lpz_trend_by_doctor`, `lpz_trend_by_doctor_kpi`,
     `lpz_department_last_date` — додано `h.doc_resource_id IS NULL AND`
     перед fallback `EXISTS` по `lpz_hospitalization_doctors`/
     `lpz_episodes`. Ці функції писались, коли `doc_resource_id` був 0%
     заповнений (коментар у коді застарів — зараз ЛШМД 91,6%, Health24
     99,8%), тому fallback ганяв дорогий підзапит по 398 тис. епізодів для
     КОЖНОЇ госпіталізації навіть коли лікар уже відомий напряму. Був
     тайм-аут (>100с) на `doctor-cabinet.html`, стало 741 мс. Семантика не
     змінилась (fallback і так шукав лише те, чого нема в
     `doc_resource_id`) — лише прискорення.
   - `lpz_department_census`/`lpz_department_icd_blocks_by_doctor` того ж
     дефекту НЕ мали — вони на `COALESCE()`, яка сама коротко замикається.

5. **Перемикач лікарень** — додано пункт «Онкоцентр» (value `43343870`) у
   `public/layout.html` (`#devOrgSwitch`) і `public/js/entry.js`
   (`renderOwnerOrgSwitch`) — той самий тимчасовий dev-перемикач, що для
   Хотинської/ЛШМД.

6. **Пілот контролю записів** — 1209 закритих госпіталізацій серпня 2026
   перевірено всіма 9 правилами ЛШМД (адаптованими під поля Health24:
   `discharge_ehealth_status` замість helsi-шного `'registered'`; діагнози
   й втручання — з `ehr/encounters` + `ehr/episodes_of_care/{id}/hospitalization`,
   ті самі коди НК 026:2021). 72 випадки з зауваженнями записано в
   `lpz_case_quality_snapshot` (single_diagnosis 61, no_interventions 8,
   overlap 8, discharge_not_registered 1, symptom_primary 1,
   injury_no_external_cause 1). **Решта 1137 «чистих» записів серпня — НЕ
   записані** (щоб не ганяти величезний SQL за раз) — для повної картини
   сегментів (відкриті/можна виправити/вже не виправити) на `quality.html`
   треба дозаписати. Повний прогін на всі 16 281 госпіталізацію — окрема
   задача (~30-40 хв за тим самим методом, ~50-80 тис. живих запитів до
   Health24).
