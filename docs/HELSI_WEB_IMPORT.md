# Прямий імпорт випадків з helsi через Chrome

**Оновлено:** 2026-07-01
**Скрипт:** `scripts/import_helsi_web.py`
**Заміняє:** старий флоу cowork (Chrome → raw_txt/PDF → `import_raw_txt.py` / `import_table_pdf.py`)

Тепер випадки госпіталізації заливаються **напряму з веб-сторінки helsi** — без проміжних PDF чи raw-txt файлів. Claude через Chrome MCP збирає текст сторінок і одразу пише в БД.

---

## Як запустити (флоу користувача)

1. Залогінься в helsi, відкрий сторінку випадків:
   `https://helsi.pro/hospital/cases?__my_patient=false`
   Переконайся, що вибране **правильне ЛПУ** (Хотинська лікарня — номери карток звичайні числа ~10000; якщо бачиш формат `№6018-2026` — вибрано ІНШЕ ЛПУ, зміни).
2. Натисни кнопку 🤖 **«Імпорт з helsi (Claude)»** на `kabinet.html` (адмінська, поруч із «Імпорт helsi PDF») — вона копіює готову команду в буфер.
3. Встав команду в чат Claude Code.
4. Claude: збирає сторінки → фільтрує по даті → ллє в БД → звітує.

**Команда, яку копіює кнопка:**
> Залий нові випадки госпіталізації з helsi. Я залогінений, сторінка відкрита: https://helsi.pro/hospital/cases?__my_patient=false . Збери сторінки і залий через scripts/import_helsi_web.py --since-db (сам візьме останню дату з БД, без дублів).

## Що робить Claude (кроки)

1. Читає останню дату госпіталізації з `lsmd` (`SELECT MAX(admission_date_d)`).
2. Chrome MCP: `navigate` на сторінку helsi → `get_page_text` (50 записів/сторінка).
3. Гортає далі кліком по `.his-ui-pagination-button--next` (через `javascript_tool`), поки не дійде до записів **старіших** за останню дату в БД.
4. Кожну сторінку зберігає у txt (формат innerText).
5. Запускає `python scripts/import_helsi_web.py <файли> --since-db --check` (dry-run), потім `--commit`.

## Скрипт `import_helsi_web.py`

```bash
# dry-run (нічого не пише): CSV + звіт
python scripts/import_helsi_web.py page1.txt page2.txt ...

# фільтр по даті госпіталізації
python scripts/import_helsi_web.py *.txt --min-date 30.06.2026

# АВТО-фільтр: min-date = остання дата в lsmd (типово використовувати це)
python scripts/import_helsi_web.py *.txt --since-db --check    # dry-run у БД
python scripts/import_helsi_web.py *.txt --since-db --commit   # запис у БД
```

**Прапори:**
- `--since-db` — сам бере `MAX(admission_date_d)` з lsmd як мінімальну дату. **Джерело правди = БД**, нічого не треба пам'ятати між сесіями.
- `--min-date DD.MM.YYYY` — ручний фільтр.
- `--check` — dry-run (відкат), `--commit` — запис.

**Дублів не буде на 2 рівнях:** `--since-db` (фільтр дати) + дедуп на вставці (`WHERE NOT EXISTS` по helsi_no + ПІБ + ДН).

## Формат сторінки helsi (для парсера)

Кожен запис у `innerText` (через порожні рядки):
```
ПІБ
№NNNNN
DD.MM.YYYY (NN р.)
Статус                (Відкритий / Закритий / На виписці / Зареєстровано… / Очікує…)
[ЕН]                  (опціонально, окремий рядок — ознака екстреної)
Госпіталізовано
DD.MM.YYYY HH:MM      (або «Не призначено»)
Виписано
DD.MM.YYYY HH:MM      (або «Не призначено»)
Місце надання послуг
…
Лікуючий лікар
Прізвище Ім'я Побатькові, Лікар-спеціальність   (або «Не призначено»)
Діагноз
ICD Опис…             (або «Не призначено»)
```
Лікар конвертується в формат `empl.emp_name`: «Савицька Юлія Анатоліївна» → «Савицька Ю. А.».

## ⚠️ Колізії helsi_no (важливо)

helsi **перевикористовує номер картки** після виписки попереднього пацієнта → один `helsi_no` у РІЗНИХ пацієнтів (напр. №10984 = Попович Інна + Попович Ірина).

**Правило:** унікальність визначається по **helsi_no + ПІБ + дата народження**, номер лишається як є навіть якщо дублюється.

Для цього **замінено unique-індекс БД**:
- ❌ було: `lsmd_helsi_no_uniq (helsi_no)`
- ✅ стало: `lsmd_helsi_patient_uniq (helsi_no, patient_name, birth_date) WHERE helsi_no IS NOT NULL`

Дедуп випадків і всі пост-INSERT UPDATE-и (`helsi_status`, `admission_type`) матчать по helsi_no + ПІБ + ДН — інакше статуси плутаються навхрест між пацієнтами-тезками за номером.

> ⚠️ Старі скрипти `import_helsi_cases.py` / `import_table_pdf.py` матчать лише по helsi_no — для них колізії = ризик. Для веб-імпорту використовувати `import_helsi_web.py`.

## Нюанси

- **Вибір ЛПУ:** якщо номери карток мають формат `№NNNN-РІК` (напр. `6018-2026`) або дати з майбутнього (2033) — вибране інше ЛПУ / тестовий заклад. Правильне: звичайні числові номери.
- **Час виписки не важливий** — рахується тільки дата; `discharge_ts = 00:00` — норма.
- **Один пацієнт, кілька випадків** (різні номери) — це нормально, окремі госпіталізації.
- **Конект до БД:** через pooler у `.env` як `SUPABASE_DB_URL` (`lsmd_db.py`).
